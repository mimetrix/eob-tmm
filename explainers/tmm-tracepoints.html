Instrument TMM by design — observe, debug, and find root cause.

A proposed set of designed-in tracepoints built into TMM's source, read in-process by the embedded eBPF VM. Each is a small typed ctx at a point in the data path; a probe reads it and the host aggregates — a counter, a histogram, a black-box ring. Below, the tracepoints laid over the data path. Why a rich catalog is affordable

Add as many as you like — they cost nothing until lit

Dark until lit

~one branch when idle

A tracepoint with nothing attached is a predictable branch. You pay only when a probe is loaded onto it, on demand — so the catalog can be broad without a standing tax.

No helpers, no verifier work

A pure read of ctx

An observe probe reads ctx and returns a value; the host does the rest. No eBPF helpers to define or secure, and stock PREVAIL verifies it — a new tracepoint needs no VM or verifier change.

Incremental

One ctx, one hook, published

Each subsystem owner instruments their own code in a normal release. The surface grows USDT-style; every new field widens what can be observed and shielded.

The producer/consumer point

These hooks and their ctx are TMM's — designed in first, emitted in the signed per-build hook-point map. A probe is always written against a ctx that already exists: a curated window onto state TMM already holds, not raw memory. That's what keeps it safe (nothing to confine — the probe can only read what the hook exposes) and durable (relocated across builds by type, fails closed if a field moves).

From signal to capability

Five patterns that turn tracepoints into RCA features

The catalog is raw signal. These reusable shapes turn it into named capabilities — each built from the same observe machinery, no helpers, no verifier work.

Pattern 01

Flight recorder

A per-CPU ring of recent ctx records, frozen and dumped on a trigger — the run-up into a fault, the blind spot a core dump can't give you. shm-backed, so it survives a crash.

record + trip: tmm:l7:parse_error · tmm:rt:watchdog
Pattern 02

Per-flow latency breakdown

Difference timestamps across ordered stage hooks into a per-stage latency profile for one flow or tenant, on demand. Answers "where did the latency go?" inside TMM.

conn_new → handshake_done → http_request → bd:request_eval → member_select → response
Pattern 03

Error-branch tripwire

Arm an error hook as a conditional recorder: cheap in steady state, it starts capturing once a leading indicator appears and freezes on the fault. Near-zero standing cost.

tmm:tls:decrypt_err · tmm:plugin:degrade · tmm:l7:parse_error
Pattern 04

Signed support probe

A narrow observe program for the exact hook + condition behind an intermittent field issue — signed, loaded read-only, captured, then pulled. In-situ RCA, no debug build, context-minimized.

any hook · time-boxed · one-way audited sink
Pattern 05

Combined play — enforce + capture

Pair a filter shield with a recorder on the same condition: the malformed frame is dropped (box survives) and the run-up into the blocked attempt is captured. Every block feeds SIRT.

tmm:l7:parse_error ◆ + flight recorder

Two ways to consume a tracepoint

Summarize it, or capture it

Same tracepoints, two thin front-ends over the embedded VM — one aggregates, one streams the actual bytes. The tcpdump-to-bpftrace pairing, for a kernel-bypassed data plane: tmmtrace : bpftrace :: tmmdump : tcpdump.

tmmtrace · summarize

Summarize — bpftrace-for-TMM

A one-liner counts, histograms, or predicates over ctx; the same grammar authors a shield by swapping the action verb. The summary-and-decision consumer.

tmmtrace run 'tmm:l7:http2_frame { @ = hist(args.n_streams); }'
tmmdump · capture

Capture — tcpdump-for-TMM

The actual bytes, not a summary — the one tap a kernel-bypassed data plane allows. The VM selects (a flow, a condition); the host streams a bounded window off the poll loop, drop-not-block. In-process at L7 → decrypted payload no wire tap can give you, at the strictest authz tier.

tmmdump --flow 10.0.0.5:443 --decrypted --snap 512

Where to start

The highest-leverage, lowest-risk hooks to land first

If the team lands a handful first: all read-only observe, cold/warm, each a ctx + a call site — no VM, verifier, or helper work. They graduate to shields (where ◆) once the signal is trusted, reusing the same hook and verify gate.

The one line

Every tracepoint is define a ctx, place a hook, publish it — so the team can make TMM the easiest thing at F5 to observe, debug, and root-cause, one release at a time.
