A runtime, programmable, provably-safe data plane.

In the generative-AI world, everything happens at machine speed — and the core of the data plane is still waiting its turn. A config push, a redeploy, a new feature, a critical mitigation: minutes, everywhere else. The data plane flexes at its edges — config, traffic logic — but changing its own code and behavior still waits on a release.

And the timing cuts F5's way. Generative AI has nothing to say about line-rate processing — the one layer it can't disrupt — and the proxy sits on a unique data source: every flow, decrypted, in context. Today that stream is digital exhaust; verified in-situ transforms make it F5's to develop, and to monetize.

One dimension — what it's for · two co-equal faces · FP²

FP Flexible Programmability

Extend what it does. New telemetry, new logic, new behavior in the running data plane — delivered as verified bytecode against designed-in hook points, no rebuild.

FP Flexible Protection

Mitigate what's live. Block a specific threat in place, in hours, with no release — a surgical, reversible control that stands in until the patched build ships on schedule.

Flexible Programmability × Flexible Protection = FP² — two faces of the form “Flexible P—,” so it squares. One verified surface, both: change the running data plane's behavior, safely, now.

TMM is a kernel. Its own scheduler, memory manager, and network stack — and it bypassed the Linux kernel, so kernel eBPF is structurally blind to it. Linux earned an in-kernel eBPF VM for exactly this job; a kernel of TMM's standing and maturity deserves its own.

The move: give TMM its own eBPF. Embed a small JIT-compiled VM (uBPF, ~150 KB) inside TMM at designed-in hook points, gated by the stock PREVAIL verifier — every program proven bounded and memory-safe before it loads. No rebuild, no reboot:

change today C source → rebuild → re-qualify → release train weeks–quarters
the move author → clang → PREVAIL verify → sign → load hours

runtime · programmable · provably safe — the combination nothing else has: iRules is runtime but never provable; WASM is sandbox-killed, not proven; kernel eBPF is provably safe but in the wrong kernel. Complementary to iRules and WASM — this reaches the layer none of them can.

A general-purpose platform — with one flagship app

  • Deep observability — inside the kernel-bypassed path: tmmtrace (bpftrace for TMM) · tmmdump (tcpdump for TMM) · flight recorder.
  • A data source, tapped — in-situ transforms on flows only the proxy sees.
  • New logic, tuning & field diagnostics — shipped as bytecode, no TMOS rev.
  • AI-authored programs — the verifier is a fail-closed gate; proof, not trust.
  • The flagship: the shield — signed, CVE-keyed, monitor→enforce, auto-retiring; mitigates live exploits nothing else reaches, on either plane.

■ the load-bearing assumption: the verifier is right

Provenance — PREVAIL is the verifier Microsoft ships in eBPF-for-Windows (abstract interpretation, production-hardened). Narrow envelope — used at its best-proven case: a pure function of a typed ctx, no helpers, no maps. Depth — F5 signing before it, a per-hook watchdog behind it; every outcome host-owned. A proof, not a promise.

Make the data plane runtime, programmable, and provably safe.

Not a feature request — a direction: treat runtime programmability and runtime security as one requirement of a machine-speed world, served by one surface spanning both planes. The parts are proven libraries; the hooks are ours to place; the safety is a proof, not a promise.
