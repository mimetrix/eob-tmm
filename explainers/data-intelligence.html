F5 TMM · data-plane intelligence · design proposal

The proxy as AI's sensory organ.

TMM terminates TLS — so it sees every flow, decrypted, in context, at line rate: the most complete view of enterprise application traffic anywhere. This page spells out the architecture that turns that view into signal which makes the proxy smarter — without ever moving the data.

01 the vantage

The most complete view of application traffic — and today it's thrown away.

Every other observer of enterprise traffic is structurally blind somewhere. The full proxy isn't — because it terminates the encryption everyone else is stuck outside of.

ObserverStructural blindness
Endpoint / EDRone host; no network context; attacker-disablable
NDR (network detection & response) / packet brokersciphertext — TLS-everywhere ended the wire view
SIEM / cloud logssamples + metadata, after the fact
The full proxy (TMM)none — sees both sides of every flow, decrypted, in context, at line rate

Two locks have kept that vantage worth nothing: you can't centralize it — exporting decrypted line-rate payloads is infeasible (bandwidth) and impermissible (privacy, residency, law) — and until now you couldn't compute on it in place, because running analytic code inline on a kernel-bypass data plane risks crashing the path or leaking the very data you must not move.

The verified substrate opens both locks. A verified program computes on the data where it lives and exports only the distilled result — kilobytes of signal, not gigabits of payload. The next section is exactly how that stays safe.

02 signal out, payload in

Compute where the data lives — and prove only the derived signal can leave.

"The payload never leaves the box" isn't a policy or a promise; it's a property that composes from two independent guarantees — one from the verifier, one from the host.

why the raw payload has no path out

verifier provesthe program has no exit of its own — with no helpers it does no I/O — and it reads only the fields the signed hook-point map declares. Its sole output is one return value.
host ownsthat single exit — a one-way, schema-checked sink the program can't read back or redirect, which accepts only derived output (a feature vector, a sketch, an inventory, an attestation), never raw bytes.

Program can't send data out · the one host channel takes only derived output → raw payload has no path off the box.

Data-minimization becomes a checkable property of the mechanism. You can even export a proof about the data in place of the data — an attestation that no field of a declared sensitivity class was emitted — which is what makes this monetizable at a regulated TLS boundary where moving traffic is forbidden.

03 reference architecture · the API-discovery MVP

Start with the lowest-hanging fruit — and it exercises the whole mechanism.

API discovery, schema-drift, and sensitive-data-exposure mapping is the entry point: an existing security market, no model needed (deterministic aggregation + light classification), entirely observe-mode (no enforcement risk; per-request/warm — no hot-path fight). Ship it, and the learning tiers are additive.

04 sense · learn · act

Once you can extract signal safely, the loop closes.

Features distilled in-situ train an F5 model; the model's output returns to the plane only as verified programs — so a model can drive the data plane while staying out of its trust path.

Only distilled features leave the box; the payload never does, and the model never touches the data path.

the pipeline, stage by stage

sense · traffic → features

  • Each verified extractor emits a bounded record; the host rolls records into per-endpoint / per-flow feature representations — counters and quantiles (latency, sizes), protocol-state-transition sequences, header/entropy stats, and event-sequence embeddings for the foundation model. Sketches (count-min, HLL) keep them compact.
  • These land in a feature store: a rolling on-box window for real-time scoring, plus periodic anonymized snapshots contributed to the fleet. Raw payload never enters it (§02).

learn · features → models

  • Pretrain (fleet, self-supervised): a foundation model learns normal from unlabeled event sequences — masked / next-event / contrastive objectives across the federated corpus. No labels needed; this is where most early value lives.
  • Fine-tune (supervised, per task): heads for exploit-behavior, exfil, bot, API-anomaly, trained on the labels you have — the exploit-replay corpus, confirmed incidents, the legitimate-traffic corpus.
  • Federate safely: only features / gradients leave each box — secure aggregation, optional differential-privacy noise; payloads confined at the sensor.
  • Distill: compress the needed heads into a small on-box SLM for low-latency, data-local scoring.

act · models → verified programs

  • The model emits a candidate — a detection predicate, a bounded tuning control, or a new feature transform — never inline action.
  • It runs the same gate as a shield: compile → static verify (fail-closed) → sign (human-gated for anything enforcing) → observe-first → auto-retire.
  • Outcomes and blocks feed back as fresh labels and features — the loop's free supervision (every block is a confirmed positive). The model proposes; the verifier disposes; the host acts.

The maturity curve is the build order: deterministic aggregation (the MVP — no model) → unsupervised anomaly/baselining → supervised heads as labels accumulate → federated self-supervised foundation model → generative authoring, every output still admitted by the verifier. Each stage ships value on its own; none blocks on the next.

a worked example — a credential-stuffing wave

The on-box SLM scores drift in login-endpoint features — failed-auth rate, IP fan-out, timing regularity — and auto-arms a monitor probe on the auth hook: reversible, no human needed. It confirms the pattern; SIRT reviews and signs a verified rate-limit / nonce-check program, deployed observe-first, then enforcing. Every block, plus the flight-recorder capture of the attempt, becomes a new label that sharpens the detector across the whole fleet — sense → learn → act, one turn of the loop.

05 the leverage

The install base is already the sensor grid.

F5 already sits in the path for a large share of the world's enterprise application traffic — so this isn't a sensor network to build, it's one already deployed, switched on by a software capability.

  • A compounding moat a latecomer can't buy. Federated across the fleet, every box makes the model better and the model makes every box better — catching up needs both the placement and the years of traffic. And the moat needs both halves: the vantage (be the proxy) and the verified in-process surface — no pure-play observability or security vendor has the first.
  • Captured in the product, not sold as a feed. The intelligence makes the proxy itself unbeatable — sharper detection, self-tuning, new capabilities — rather than being spun out as a data feed.
  • Monetizable where no one else can even collect. Because the signal leaves while the payload can't, F5 can build on data at a regulated TLS boundary where everyone else is forbidden even to gather it.

06 the thesis

The data plane becomes AI's sensory organ — and AI returns to it as verified bytecode.

Turn traffic only F5 can see into governed signal it never has to move; compute it where it lives; close the loop by letting models return to the plane only as verified programs. One vantage, one substrate — a data advantage that is F5's alone to build, and safe by construction to operate.
