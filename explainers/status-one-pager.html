Extending a shipped data plane in place — now with the cost measured

TMM is already programmable: iRules run in it live. But an iRule sees only the objects F5 exposed, at the events F5 placed, frozen when the binary shipped. This loads verified bytecode at any function entry of a running TMM — no rebuild, no restart, no dropped traffic — so the data plane gains observability and per-flow logic no shipped event reaches, and its behaviour stops being fixed at ship time. The open question was always cost. It is now answered.

This is the number that settles it. A kernel uprobe traps in and out at roughly a microsecond — unusable at data-plane rates, and it can neither change a return value nor be statically verified. An in-process verified trampoline does the same reach for ~9 ns and can enforce. That gap is the whole reason to build this inside TMM.

The next build — displacement: attach where there is no pad

Why it is needed

Arming today overwrites five nop bytes the compiler reserved at a function's entry — nothing is displaced, so disarm restores byte-identical code and the data plane is never disturbed. But that pad exists only in TMM core. Components built separately — the linked OpenSSL among them — have no pad, and ls_arm refuses them today. The same limit is why the fixes that matter most, whose checks read a value the function computes, sit past a reachable entry.

index today: 41,148 padded (armable) · 30,009 pad-less, marked DISPLACEABLE

What it is

1 · overwrite the first instructions with a 5-byte jump to the trampoline, instead of a reserved pad.
2 · re-run the displaced bytes from the trampoline, then continue into the function body.
3 · the hard part is safety — a copied instruction whose encoding depends on its address (a relative call or jump) points to the wrong place once moved.
4 · disarm restores the original leading bytes.

Why it is tractable here

Frida does this at runtime and must ship a full instruction decoder. We do not decode anything in the data plane. A measurement makes it unnecessary: of TMM's 79,794 function entries, 94.8% begin with position-independent instructions — copyable byte-for-byte with no re-encoding.

So the classification runs offline, at build time, where the toolchain is free; the runtime is left with a memcpy and a jump. Anything not provably copyable is refused, not guessed — fail-closed, the same rule as the safe-return gates.
